# Predicting Song Popularity on Spotify Using Audio Features

Predictive Analytics course project. Investigates how much of a track's Spotify popularity
score is explained by its audio characteristics, and where the remaining signal lives.

## Headline results

| | Audio only | Audio + genre |
|---|---|---|
| Linear Regression R² | 0.034 | 0.324 |
| Best tuned model R² (Random Forest) | **0.266** | **0.501** |
| Best tuned classifier ROC-AUC | 0.724 (Random Forest) | 0.873 (Gradient Boosting) |

Held-out test-set results for the validation-selected, CV-tuned models, with the classifier
cut at popularity ≥ 50. The DA1 proposal reported preliminary untuned figures (R² 0.255 /
0.483) from an earlier scoring of the same test set; no setting was chosen by looking at it.

**Seed variance.** Refitting the tuned Random Forest on five different train/validation
partitions (seeds 42, 1–4, test set held fixed and not rescored) gives validation R²
**0.250 ± 0.013** audio only and **0.498 ± 0.009** audio + genre (mean ± SD), so the
≈0.25 gain from genre is far larger than the seed-to-seed spread
(`src/run_seed_variance.py` → `data/processed/results_seed_variance.csv`).

| External validation (Hit Predictor, 37,431 unseen tracks) | |
|---|---|
| Transfer ROC-AUC, audio-only model trained on Spotify popularity | 0.69 |
| … for 1960s tracks → 2000s tracks | 0.59 → 0.80 |
| Decade predicted from audio alone (CV R²) | 0.52 |

**Finding.** Audio features alone explain about a quarter of the variance in popularity, and
almost none of it linearly. Genre context nearly doubles explanatory power and outweighs the
strongest individual audio feature (`log_duration`) by roughly thirteen times. The audio signal
generalises to an independent hit/flop label, but works far better for recent decades and
partly encodes *when* a song was made. How a song *sounds* constrains its popularity far less
than what category it occupies and when it was released.

## Data

The Spotify Tracks Dataset — 114,000 tracks × 21 columns, BSD licensed, retrieved from its
[HuggingFace mirror](https://huggingface.co/datasets/maharshipandya/spotify-tracks-dataset)
(also on [Kaggle](https://www.kaggle.com/datasets/maharshipandya/-spotify-tracks-dataset)).

> Spotify deprecated the `audio_features` and `audio_analysis` Web API endpoints on
> **27 November 2024**; new applications receive `403`/`410` and no replacement exists. This
> data therefore cannot be collected first-hand — the project uses an archived
> pre-deprecation snapshot. See the report's Limitations section.

Two structural properties of the raw file drive the methodology:

- **21.3% of rows are duplicates.** The file is 114 genres × 1,000 tracks and a track can
  appear under up to 9 genres. Splitting before deduplication puts the same song in train and
  test. Deduplication yields 89,741 unique tracks.
- **The target is zero-inflated and the zeros are genre-clustered** (jazz 68%, iranian 66%),
  which points to regional availability gaps rather than unpopular music.

**External dataset.** [The Spotify Audio Features Hit Predictor Dataset (1960–2019)](https://data.4tu.nl/datasets/a3094315-d0d6-4326-8194-1536c709fa93)
(F. Ansari, 4TU.ResearchData, DOI 10.4121/uuid:d77e74b0-66bc-47ac-8b25-5796d3084478, GPL-3.0)
— about 41,000 tracks with the same audio features, a decade, and a Billboard-based hit/flop
label. 3,100 tracks also present in the primary dataset are removed (1,922 by Spotify ID,
1,178 more by artist + title, since re-releases get new IDs).

## Reproducing

```bash
pip install -r requirements.txt
```

Both datasets are downloaded on first run and checked against the exact files the study
used: `data_prep.py` fetches `dataset.csv` from the HuggingFace mirror pinned to revision
`635b034f` (SHA-256 checked), and `external_data.py` fetches the Hit Predictor archive from
4TU (MD5 checked). Downloads retry with backoff on rate limits and server errors.

```bash
python src/data_prep.py && python src/tuning.py && python src/run_regression.py && python src/run_classification.py && python src/run_interpretation.py && python src/run_shap.py && python src/run_final_test.py && python src/external_data.py && python src/run_external.py && python src/make_notebook.py
```

```bash
python -m pytest tests
```

The test suite (under a minute) checks the split sizes and leakage guarantees, the
deduplication and feature engineering, the external overlap removal, and the download
retry and checksum logic (offline); tests that need the downloaded data skip when it is
absent.

`tuning.py` is the slow step (roughly an hour on a 16-core laptop). Every later script falls
back to hand-set defaults if `best_params.json` is absent.

| Script | Purpose |
|---|---|
| `src/data_prep.py` | Raw download (SHA-256-checked), deduplication, cleaning, feature engineering, stratified split with leakage assertions |
| `src/models.py` | Model definitions, tuned-parameter loading, the two-stage hurdle regressor, evaluation helpers |
| `src/tuning.py` | Randomised/grid CV search inside `train.csv` only → `best_params.json` |
| `src/run_regression.py` | RQ1/RQ3 — regression across both feature sets, plus the shuffle check |
| `src/run_classification.py` | RQ4 — binary framing at two thresholds |
| `src/run_interpretation.py` | EDA figures, VIF, permutation importance |
| `src/run_shap.py` | SHAP summary (isolated — `TreeExplainer` is the slow step) |
| `src/run_final_test.py` | Single held-out test evaluation of the validation-selected models, plus confusion matrices |
| `src/external_data.py` | Downloads (MD5-checked) and prepares the Hit Predictor dataset, removing tracks shared with the primary set |
| `src/run_external.py` | External transfer test and the era-confound measurements |
| `src/run_seed_variance.py` | Validation R² of the tuned Random Forest across five train/validation seeds |
| `src/make_notebook.py` | Regenerates the notebook from source |

## Leakage controls

Popularity modelling on this dataset fails quietly in several ways, so the defences are
explicit:

- **Deduplication before splitting**, with assertions that no `track_id` appears in more than
  one partition (`data_prep.split`).
- **All preprocessing inside a `Pipeline`**, so scalers and encoders are fitted per fold and
  never see held-out data.
- **Artist features deliberately excluded.** Artist mean popularity is the strongest available
  predictor but leaks the target unless computed out-of-fold under artist-grouped splits.
  Omitting it caps accuracy and keeps the study faithful to its title.
- **Shuffled-target check** — refitting on a permuted target collapses R² to −0.0009.
- **Tuning inside `train.csv` only** — validation and test are never loaded by `tuning.py`.
- **External overlap removal** — no Hit Predictor track used for validation is in the
  primary dataset, by ID or by artist + title.
- **The test set is evaluated once**, after all modelling decisions are fixed.
